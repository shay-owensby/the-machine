# Testing and validation

Retrieval is separated from analysis so the analytical half — where the
judgement lives, and where a bug produces a confidently wrong sentence rather
than a crash — can be tested against fixed data, offline, in a second.

```bash
python3 scripts/run_tests.py            # 130+ assertions, no network
python3 scripts/run_tests.py --verbose  # name every case
```

## What is covered

| Area | Cases |
|---|---|
| Credentials | Missing `agency.env`; missing individual variables; quoted and `export`-prefixed values; complete configuration |
| Client config | No account named anywhere; malformed customer ID; `GOOGLE_ADS_LOGIN_CUSTOMER_ID` supplying the account; the shared-value fallback warning; explicit account plus manager header; a client overriding the agency manager; CLI overriding both |
| Account shape | Login ID equal to target (querying the manager); manager and test accounts |
| Secrets | No secret appears in `describe_config()` output; credentials render as `present` |
| API errors | Permission denied; unapproved developer token; quota exhaustion; non-JSON 5xx |
| Resilience | Retry on transient 503; persistent 429 raising a retryable error; one forced token refresh on 401; pagination; API version fallback |
| No conversions | CPA unavailable rather than zero; the anomaly fires; tracking verification is the top recommendation |
| No conversion value | ROAS and conversion value unavailable; both absent from the KPI table; both listed as unavailable |
| Zero comparison period | Percentage change undefined; verdict `new`; absolute change still reported; no division by zero |
| Sparse data | Account and campaigns flagged; no high-severity campaign findings; conversion-derived findings capped at medium confidence |
| Paused campaigns | A paused campaign that spent is called out as not like-for-like |
| Partial availability | Failed queries surface as errors and warnings; Performance Max reports no impression share; core KPIs still report |
| Placeholder values | A flat per-conversion value is flagged, with its effect on ROAS |
| Invariants (every fixture) | No unavailable KPI printed as a number; no percentage from a zero baseline; every finding has evidence, severity and confidence; recommendations reference real findings; periods stated; no NaN or Infinity in the contract |
| Charts | Six charts draw for a complete account; files exist; each has title and alt text; the manifest writes back; an undrawable chart is skipped **with a reason** |

## The fixtures

`assets/fixtures/*_raw.json`, generated by `scripts/make_fixtures.py`:

| Fixture | The awkward case |
|---|---|
| `healthy` | Growth, four campaigns, mixed types, full metric availability |
| `no-conversions` | Real spend, zero conversions |
| `no-conversion-value` | Lead gen: conversions but no value, so no ROAS |
| `zero-previous` | Brand-new account; the comparison period is all zeros |
| `sparse` | Tiny volumes, plus a paused campaign that still spent |
| `partial-failure` | Two failed queries; Performance Max reporting no impression share |
| `placeholder-value` | A flat 1.00 conversion value masquerading as revenue |

They are REST-shaped: camelCase keys, int64 as strings, cost in micros,
conversion value as a plain double, and **absent keys** where an account cannot
report a metric. That last detail is what makes them worth having — the
unavailable-versus-zero rule is only testable against data that actually omits
things.

Numbers are round and deterministic so assertions can be exact. Regenerate after
changing the generator:

```bash
python3 scripts/make_fixtures.py
python3 scripts/make_fixtures.py --list
```

## Testing against a real account without writing a report

```bash
python3 scripts/check_config.py --project-root ~/clients/<client>       # auth + account identity
python3 scripts/fetch_google_ads.py --project-root ~/clients/<client> \
  --out /tmp/ads-test --days 7 --skip search_terms,keywords             # small, cheap
python3 scripts/analyze_performance.py --raw /tmp/ads-test/*_raw.json --out /tmp/ads-test
```

A seven-day window with the expensive datasets skipped is a handful of queries.
Keep the raw file: it becomes a fixture for any bug you find, once the account
name and customer ID are replaced with placeholders.

## Adding a case

1. Add a `fx_*` function to `make_fixtures.py` returning `envelope(...)` with
   the datasets that matter. Omit keys the case is about — omission is the
   scenario.
2. Register it in `FIXTURES` with a one-line description.
3. Add a `test_*` in `run_tests.py` asserting on the **analysis output**, not on
   internals: what the KPI table says, which findings fired, what
   `data_quality` warns about.
4. `python3 make_fixtures.py && python3 run_tests.py`.

## Checking the tests actually bite

A suite that passes against broken code is worse than no suite. Mutate something
and confirm failures:

```bash
cp scripts/analyze_performance.py /tmp/backup.py
# make percentage change against a zero baseline return 100.0 instead of None
python3 scripts/run_tests.py     # expect: 3 failures naming the zero-baseline rule
cp /tmp/backup.py scripts/analyze_performance.py
```

Worth repeating after any substantial change to the analysis engine.

## Before a client report goes out

- [ ] `check_config.py` returns 0 and the **account name matches the client**
- [ ] Both date ranges appear in the report, and match the analysis file
- [ ] Every figure in the report exists in `analysis.json` (spot-check three)
- [ ] Every `data_quality.warnings` entry is reflected in the report
- [ ] No metric marked `unavailable` appears as a number or a zero
- [ ] Every recommendation names a campaign or a metric and cites a figure
- [ ] Charts referenced in the report exist on disk; skipped charts are not described
- [ ] Nothing in the report or logs contains a token, secret or credential value
